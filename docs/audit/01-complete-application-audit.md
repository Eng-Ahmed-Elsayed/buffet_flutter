## 1. System Architecture & Domain Model Map

### Roles & Responsibilities

| Role (`UserRole`) | Surface(s) | Primary Responsibilities |
|---|---|---|
| **Employee** | Flutter Mobile (`EmployeeShell`), MVC (`Orders`, `MyMaterials`, `Notifications`) | Order drinks (self or guest when `CanOrderForGuests = true`), save/replay favourites, view own orders (`Pickup` / `Delivery`), declare personal materials brought in, receive notifications |
| **Staff** | Flutter Mobile (`Staff` Queue & Self-order), MVC (`Staff`, `Orders`, `Notifications`) | Work live queue (`Pending` / `InProgress`), start orders, mark `Ready` (deducting stock and emitting shortage warnings), hand over `Completed` orders, cancel orders (booking waste if already `Ready`) |
| **Admin** | MVC Admin Panel (`Inventory`, `Stocktake`, `DrinkGroups`, `MenuOrder`, `Locations`, `Reports`, `Users`, `Materials`, `Templates`, `Audit`) + API `/staff/declarations` | Manage company catalogue (`Drink`, `Sugar`, `Extra`), variants & allowed extras, drink groups & menu order, delivery locations, stocktakes & variance reports, employee personal-material confirmations/rejections, bulk Excel templates, user management, and audit logs |

### Critical Domain Workflows & End-to-End Trace

1. **Order Lifecycle (`OrderStatus`):**
   - `Pending` -> (`POST /orders/{id}/start`) -> `InProgress` -> (`POST /orders/{id}/ready`) -> `Ready` -> (`POST /orders/{id}/complete` or `POST /orders/{id}/collected`) -> `Completed`.
   - Staff can also mark `Pending` -> `Ready` directly, or `Ready` + deliver in one step (`deliverNow=true`).
   - **Stock Deduction Invariant:** Stock is deducted when reaching **`Ready`** (the physical preparation moment, setting `ReadyAtUtc` so `OrderHeader.StockDeducted` becomes `true`), **never** deferred until `Completed`. Shortages generate `StockWarningDto` warnings without blocking preparation.
   - **Waste Reversal Invariant:** Cancelling an order before `Ready` reverses no stock; cancelling a `Ready` order reverses the requester's consumption and re-books it under `TransactionReason.Waste` (`StaffApi.ReverseAsWasteAsync`) so stock balances stay accurate while consumption reports exclude uncollected drinks.
2. **Personal Materials & Private Items:**
   - Employees declare existing company items or bring unlisted items via `/materials/declare` or `/materials/declare-new` (`MyMaterialsController` on web, returning `202 Accepted` on API).
   - **Approval Gate:** Declarations and newly created private items (`!item.IsCompanyItem`, `IsPublished = false`) create **zero balance** and stay invisible until an **Admin** (enforced via `AuthConstants.AdminOnly`) confirms physical receipt (`PersonalStockService.ConfirmAsync`).
3. **Closed Delivery Locations:**
   - Employees pick from active managed `Location` rows (`LocationId` sent on `PlaceOrderApiRequest`), leaving `locationText` managed cleanly without arbitrary free-typed delivery destinations.
